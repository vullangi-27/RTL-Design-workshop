# VSDBabySoC – RTL Verification, Synthesis and Gate-Level Validation

## Overview

VSDBabySoC is a compact System-on-Chip design that combines a RISC-V processor core with analog interface blocks. The design uses the **rvmyth RISC-V core**, **avsdpll** for clock generation, and **avsddac** for digital-to-analog conversion.

This project demonstrates the complete digital implementation and verification flow, starting from obtaining the source code and ending with gate-level verification. The major stages include RTL simulation, logic synthesis using Yosys, examination of the synthesized netlist, Gate-Level Simulation (GLS), and comparison of RTL and synthesized results.

### Main Flow

**Project Setup → RTL Simulation → Yosys Synthesis → Netlist Inspection → GLS → Waveform Comparison**

---

# 1. Project Setup

A separate working directory was first prepared for the BabySoC project. The design repository was then downloaded using Git.

```bash
mkdir baby_soc
cd baby_soc/
git clone https://github.com/Subhasis-Sahu/BabySoC_Simulation
cd BabySoC_Simulation
```

Creating a separate project directory helps keep the source files, simulation outputs, and synthesized netlist organized.

# 2. Design RTL and Testbench

The main RTL design is represented by the **vsdbabysoc** top-level module. It integrates the processor core with the PLL and DAC blocks.

The testbench provides the required clock and reset signals and monitors the important output signals generated by the SoC. In particular, the `RV_TO_DAC[9:0]` signal is observed to verify the data transferred from the RISC-V core toward the DAC.

The testbench supports different simulation configurations using compiler definitions. This allows the same testbench to be used for both pre-synthesis and post-synthesis verification.

---

# 3. RTL Simulation

Before performing synthesis, the original RTL was simulated to establish a reference waveform.

The following command was used to compile the design for pre-synthesis simulation:

```bash
iverilog -o ./pre_synth_sim.out -DPRE_SYNTH_SIM src/module/testbench.v -I src/include/ -I src/module/
```

The generated simulation executable was then run:

```bash
./pre_synth_sim.out
```

After simulation, the generated VCD waveform file was opened using GTKWave:

```bash
gtkwave pre_synth_sim.vcd
```

### Signals Observed

The important signals checked during RTL simulation included:

* `CLK`
* `reset`
* `OUT`
* `RV_TO_DAC[9:0]`

The RTL waveform acts as the **reference result** for comparison with the later gate-level simulation.

# 4. Logic Synthesis with Yosys

After confirming the RTL behavior, the design was synthesized using **Yosys**.

The required Verilog source files were first loaded:

```bash
read_verilog src/module/vsdbabysoc.v
read_verilog -I src/include/ src/module/rvmyth.v
read_verilog -I src/include/ src/module/clk_gate.v
```

The required library models were then read into Yosys:

```bash
read_liberty -lib src/lib/avsdpll.lib
read_liberty -lib src/lib/avsddac.lib
read_liberty -lib src/lib/sky130_fd_sc_hd__tt_025C_1v80.lib
```

The top-level module was selected and synthesized:

```bash
synth -top vsdbabysoc
```

The flip-flops were mapped to cells available in the SKY130 library:

```bash
dfflibmap -liberty src/lib/sky130_fd_sc_hd__tt_025C_1v80.lib
```

Further optimization and technology mapping were performed using:

```bash
opt
abc -liberty src/lib/sky130_fd_sc_hd__tt_025C_1v80.lib
```

Additional cleanup and normalization steps were carried out:

```bash
setundef -zero
clean -purge
rename -enumerate
```

Finally, the synthesized design statistics were displayed and the resulting gate-level Verilog netlist was generated:

```bash
stat
write_verilog -noattr baby_soc_net.v
```

The `stat` command provides information about the synthesized design, including the cells used after technology mapping.

# 5. Synthesized Netlist Inspection

The generated netlist was inspected to understand how the original RTL design was transformed into hardware.

Two types of views were considered.

## 5.1 Hierarchical / Block-Level View

At the higher level, the netlist shows the major functional blocks of the BabySoC.

The **avsdpll** provides the clock to the processor section. The **rvmyth** core generates the digital output data, which is transferred through the `RV_TO_DAC` bus to the **avsddac** block. The final analog-related output is represented by `OUT`.

This view is useful for understanding the overall connectivity between the main modules without dealing with individual standard cells.

## 5.2 Technology-Mapped Gate-Level View

After Yosys and ABC mapping, the internal logic is represented using cells from the **SKY130 standard-cell library**.

The resulting diagram contains a large number of interconnected logic gates and wires. Unlike the block-level representation, this view focuses on the actual implementation of the digital logic.

The dense appearance of the diagram is expected because the original RTL has been converted into individual standard-cell instances.

# 6. Gate-Level Simulation

Once synthesis was completed, the generated netlist was used for Gate-Level Simulation.

For GLS, the synthesized netlist is simulated together with the Verilog models of the SKY130 standard cells. The post-synthesis simulation configuration was selected using `POST_SYNTH_SIM` and `FUNCTIONAL`.

The compilation command was:

```bash
iverilog -DPOST_SYNTH_SIM -DFUNCTIONAL \
-I src/include/ \
-I ../../sky130RTLDesignAndSynthesisWorkshop/my_lib/verilog_model/ \
-I src/module/ \
src/module/testbench.v
```

The compiled simulation was executed using:

```bash
./a.out
```

The resulting waveform was then opened in GTKWave:

```bash
gtkwave post_synth_sim.vcd
```

The purpose of this stage is to verify that the synthesized gate-level implementation still produces the expected functional behavior.

# 7. RTL and GLS Waveform Verification

The pre-synthesis and post-synthesis simulation results were compared using GTKWave.

The following signals were examined:

* `CLK`
* `reset`
* `RV_TO_DAC[9:0]`
* `OUT`

The `RV_TO_DAC[9:0]` bus was especially important because it represents the digital data passed from the processor toward the DAC.

The RTL and GLS waveforms showed the same functional behavior over the observed simulation period. No functional discrepancy was observed between the original RTL implementation and the synthesized gate-level design.

This comparison provides confidence that the synthesis process did not alter the intended logic functionality.

# 8. Final Result

The VSDBabySoC design was successfully processed through the complete RTL-to-gate verification flow.

The major steps completed were:

1. BabySoC repository setup
2. RTL and testbench identification
3. Pre-synthesis RTL simulation
4. Synthesis using Yosys
5. SKY130 standard-cell technology mapping
6. Synthesized netlist generation
7. Netlist visualization
8. Gate-Level Simulation
9. RTL versus GLS waveform comparison

The comparison of the important signals showed consistent behavior between RTL simulation and GLS. Therefore, the synthesized implementation was verified to preserve the intended functional operation of the original VSDBabySoC RTL.

## Conclusion

This experiment demonstrates a complete digital ASIC design verification flow for VSDBabySoC. Starting with the RTL description, the design was simulated, synthesized using the SKY130 technology library, converted into a gate-level netlist, and subsequently verified through Gate-Level Simulation.

The agreement between the RTL and GLS waveforms indicates that the synthesis and technology-mapping stages maintained the functional behavior of the design. Thus, the project provides practical exposure to the RTL-to-GDS-oriented verification stages used in digital VLSI design.
